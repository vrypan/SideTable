# Architecture and implementation limits

[Documentation](README.md) · [SideTable](../README.md)

`Sidetable/` contains the native application, feature views, and platform integrations. `Packages/ApronCore/` contains the independent wire models, reducer, transport, session, fixtures, and probe. App and UI tests live in `SidetableTests/` and `SidetableUITests/`. Design and implementation plans stay under [`plans/`](../plans/001-macos-client-design.md).

## Application ownership

`AppModel` coordinates application services, server sessions, and link resolution. It owns a `ConversationWorkspace` and forwards navigation properties and operations to it so views observe a single source of truth. `ServerModel` holds each server's snapshot and account-scoped resources; `PreviewData` installs sample state independently of application startup.

`ServerModel` owns a `ServerConnection`, which manages its live `ApronSession`, event listener, and authentication operation identity. The connection serializes startup after stopping the previous session and suppresses stale sign-in completions. Its session factory and browser opener can be injected for tests. `ServerModel` forwards session access and observable busy state for existing callers. `AppModel` supplies credentials and consumes session events to update snapshots, navigation, notifications, and caches; saved-account policy and sign-out cleanup remain there.

`ConversationWorkspace` owns panel order, focus, sidebar server selection, per-panel search access, and navigation restoration. Browsing another server does not move the active panel; focusing a panel selects its server. Navigation operations receive the current server list and update each server's selected room. The workspace has no session or networking operations. Synchronous callbacks let `AppModel` cancel link resolution on navigation and present storage errors.

The workspace reads and writes `panels-v1.json` and the legacy `location-v1.json` without changing their formats. Startup restores server selection before cached rooms, restores panel layout afterward, then enables persistence. An explicitly empty panel layout remains empty. Restored panels wait for their room load before missing rooms are discarded; account mismatches are rejected. Inspector preferences, drafts, read markers, and conversation caches remain outside the workspace.

`ConversationView` owns a transient `ConversationComposerState` for its lifetime. The state holds the inline editor, focus restoration, insertion requests, attachment chooser presentation, and link preview loader. Edit completion is tied to the editor identity so a late callback cannot dismiss a newer edit. Draft text and staged files remain in `AppModel` and `ServerModel`; starting or closing an edit does not replace the unsent draft. SwiftUI tasks still own preview refresh cancellation.

`ConversationTranscriptState` owns viewport bookkeeping, history anchors, live-arrival counts, and the unread divider for the same view lifetime. Its synchronous transitions distinguish requesting Latest from reaching it and user scrolling from programmatic positioning. The view still performs scrolling, loads history in cancellable SwiftUI tasks, and publishes attention to `AppModel`. Conversation panels retain their server/account/room identity so replacing a conversation creates fresh transient state.

Views are grouped under `Features/Authentication`, `Features/Servers`, `Features/Conversations`, `Features/Messages`, and `Features/Settings`. Native integrations and media caches remain under `Platform/`; for example, attachment presentation lives with message views while `AttachmentRenderCache` lives under `Platform/Media`.

## Core session ownership

`ApronSession` remains the single actor coordinating transport, protocol state, and recovery. `SessionSnapshot.swift` defines its public snapshot and event values; `SessionEventBuffer.swift` owns the synchronized event queue. `PendingRequests` is a synchronous helper confined to the session actor, pairing each RPC continuation with its timeout task and removing both before completing a request. Generation checks, sending, cancellation handlers, and request-limit policy remain in the actor.

## Branding

The app and Dock icon use `Sidetable/Resources/SideTable.icns`, copied directly from `brand/SideTable-Brand-Kit-v2/apps/macos/SideTable.icns`. The v2 icon uses an espresso-brown (`#3B2118`) symbol on golden yellow (`#FFD23F`), with transparent outer margins and reinforced artwork at small sizes. Follow the [v2 brand guide](../brand/SideTable-Brand-Kit-v2/guide/SideTable-Brand-Guide-v2.md) for future updates. To repackage the supplied PNGs, run `iconutil -c icns brand/SideTable-Brand-Kit-v2/apps/macos/SideTable.iconset -o Sidetable/Resources/SideTable.icns`. Its bundle setting is maintained in `project.yml`; regenerate the Xcode project after changing that configuration. `assets/SideTable-dark.svg` is the previous monochrome variant and is no longer used by the app.


## Implementation limits

This is an initial working client, not complete web-client parity. Native passkeys, remote push/APNs, streaming/HTML embeds, Markdown tables/extensions, syntax highlighting, and multiple accounts on one endpoint are not implemented. CommonMark blocks render natively. Parsing is limited to 64 KiB of input, 32 levels of nesting, and 4,096 nodes; over-limit content falls back to bounded plain text, with the full source available through Copy Text. Uploads are session-only: quitting stops transfers. Retry Same Operation retains files when acknowledgement is lost. Upload links are single-use, so an interrupted PUT offers Reattach to Composer rather than silently resending the message. Retry Upload is available only for a failure before any network transfer. A successful PUT waits for the server’s attachment snapshot; cancelling locally does not delete the message.

Attachment downloads are limited to 64 MiB and automatic image downloads to 8 MiB. Composer website previews use macOS Link Presentation, with a ten-second metadata timeout, at most three concurrent links, and downsampled images held in memory for the active draft. The system manages those downloads; SideTable retains and decodes image representations only up to 8 MiB. A parallel, ephemeral HTTP request reads at most 1 MiB of page HTML, following HTTP(S) redirects without cookies or stored credentials. The system libxml2 HTML parser extracts OpenGraph tags without executing scripts or loading external resources. Available `og.image` URLs and image attributes accompany outgoing link embeds as hints for the server to proxy or replace; image bytes are not submitted. Attachment media loading is restricted to the server’s origin and its declared media origins. Cached files can be displayed without another download. See [usage and storage](usage.md) for cache behavior.

Custom emoji have a separate in-memory cache per server and account. The catalog is loaded on demand only with `ext:emoji`; changing the account, catalog URL, or capability cancels pending loads and clears the cache. Catalogs are limited to 1 MiB and 4,096 entries. Images use the avatar URL/raster policy and a 2 MiB download bound, with at most four concurrent image requests. The decoded cache holds at most 256 assets and 32 MiB per server; individual animations are bounded to 120 frames and 8 MiB at a maximum 128-pixel side. Oversized animations use a still frame. Reduce Motion uses `static_url` when available, otherwise the first frame. Catalog URLs and image data are not persisted. Unknown or unavailable emoji retain text/placeholder fallbacks; hidden entries render in history but are absent from the picker and completion list. Native selection copies rendered emoji as their original keys, and code spans/blocks remain literal.

History starts with a recent page and loads older pages on demand, while the transcript reveals messages in batches of 150. Very large logs still need further profiling. UI automation and public native connectivity are environment-dependent; see the recorded verification results in [the implementation status](../plans/003-implementation-status.md).
