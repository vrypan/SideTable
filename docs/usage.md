# Usage and storage

[Documentation](README.md) · [SideTable](../README.md)

## Connecting

Click **Add Server**, enter a hostname or full WebSocket URL, then choose a sign-in method offered by the server. Explicit paths are preserved.

- Public demo: `wss://server.apron.chat/`. Guests can read; posting is controlled by the server. Native passkeys are not yet supported, so to post from SideTable, sign in at [web.apron.chat](https://web.apron.chat) (or create an account with a passkey there), send `/invite-device mac` in any room, and paste the token or sign-in link from the reply into **Sign in with a token**. Each account can have three named device tokens; sending the command again with the same name replaces that token. Tokens do not expire, so keep them private.
- Local reference server: `ws://127.0.0.1:8080/ws`.

Manage servers in **Settings > Servers**, also reachable with **Edit Server List…** in the **Servers** menu or by right-clicking the server name at the top of the sidebar. Use **+** and **−** to add and remove servers, and drag to reorder them. Select a server to see its status and account, reconnect, sign out, forget saved accounts, or edit its address. Changing only the path (for example adding `/ws`) keeps saved sign-ins; changing the host signs out and deletes them, so a token is never sent to a different host. Switch servers from the **Servers** menu, with ⌥⌘1–9 for the first nine, or from the right-click menu on the server name. Removing a server deletes its drafts, saved conversations, downloaded media, and saved sign-ins on this Mac.
- Remote endpoints require `wss://`. Unencrypted WebSockets are allowed only on loopback addresses.

Apron protocol versions 8 and 9 are supported. Guest, token, email-code, and v9 browser-code sign-in are supported when advertised by the server. The token field also accepts a `https://link.apron.chat/#…&token=…` sign-in link for the same host. When a server offers no email or browser sign-in, the token section starts expanded. For browser sign-in, choose **Open Sign-in Page**, sign in or create an account on the website, then enter its code in SideTable. The website may offer passkeys. Email and browser codes must be entered on the connection that requested them; request a new code after reconnecting. While the sign-in screen is idle, SideTable does not ping the server or reconnect if the server closes the connection; it reconnects when you sign in or request a code. The connection is kept alive only while a code is pending. Saved tokens are kept in Keychain. Text drafts and a bounded saved-conversation history stay in the app’s Application Support directory. Sign-out removes the account’s local data on this Mac (drafts, saved conversations, downloaded media) but keeps its token in Keychain. The sign-in screen lists every account you have signed out of on that server, most recent first, each with **Continue as @account** and **Forget**, so you can switch between several accounts on one server. One account is signed in at a time. Guest identities are not kept. Removing the server deletes all its saved tokens. Signing out does not revoke a token on the server. Staged attachments are not persisted.

## Features

- Multiple independently connected servers, room discovery/join/leave, private rooms, threads, and member management.
- User profiles with name, user ID, roles, presence, and avatars. Click a message author, a member, or your account to open a profile.
- Messages, replies, explicit mentions, reactions, edits, deletion, moves, and server commands, subject to advertised capabilities and policy.
- Per-room text drafts, selectable text, adjustable message size, local find, and a keyboard conversation switcher.
- Ordered protocol processing, recent-page startup, on-demand older history, fixed-head reconnect recovery, retention resets, reconnect backoff, and uncertain-delivery handling.
- Native Markdown paragraphs, headings, lists, quotes, and selectable code blocks with Copy Code. Raw HTML and Markdown images stay inert.
- File staging and per-file upload progress, cancellation, and recovery controls; inline images, bounded downloads, and Quick Look. Media on origins not declared by the server remains an explicit browser link.
- Local mention/reply notifications, server status and mute controls, and account-scoped cached launch views.

## Conversations

The window shows the servers and rooms sidebar, the members sidebar, and one conversation. Click a room or thread, or use Command-K, to switch conversations. Command-click also selects a single conversation. There are no conversation resize handles, horizontal panel scrolling, or extra conversation panels.

Joined conversations stay updated while you browse elsewhere. Switching back uses local state instead of fetching history again. First visits load missing information, reconnecting recovers missed changes, and unjoined rooms or threads refresh when opened. To request fresh history and room details yourself, right-click a room and choose **Refresh Conversation** (or **Refresh Replies** for a thread).

Each conversation keeps its draft, reply target, and reading position. Cached messages appear while the connection checks for updates. Command-F searches the displayed conversation. Threads replace the displayed conversation; **Back to Room** in the thread’s context menu returns to its parent.

The conversation fills the space beside the two sidebars. The members sidebar can expand, collapse, and resize. Saved multi-panel layouts migrate to their last active conversation, falling back to the first valid conversation if necessary. Other rooms remain accessible from the rooms sidebar, with drafts and reading positions preserved. An explicitly empty saved layout still opens without a selected conversation.

Threads in the sidebar are sorted by latest known activity. Rows show a thread description, or a loaded message excerpt when no description is available, plus activity age and unread count. The four most recent threads stay visible, along with selected and unread threads. Expand **Other threads** to see the rest.

## Room details and controls

The standard macOS title bar shows the room or thread name and member count. Right-click a room or thread in the sidebar for **Find in Conversation…**, **Room Details…**, and its available actions. Command-F searches the displayed conversation. The people icon at the top of the members sidebar expands or collapses it. Collapsed members leaves a narrow strip with the member count beneath the icon and a scrollable avatar list below it. Green dots mark online members. Hover over an avatar for member details or click to open the profile; expanded members extends to the top edge of the window. Drag its divider to resize it. The members column follows the active discussion as you click or open other conversations; its header identifies the discussion and server. Choose **Room Details…** to read the description and privacy details, including participant avatars for private rooms.

Right-click a room or thread in the sidebar to copy a room link, edit its title and description, mute notifications for one hour, eight hours, or until resumed, unmute, or leave. Leaving asks for confirmation. Editing preserves privacy and other room settings; the server decides whether the action is allowed. A private room's title can be left empty to show its members instead. Shared links do not grant access to private rooms. Muted rooms and threads show a monochrome crossed-out bell and time remaining at the right of their sidebar row. Fixed-width labels keep the bells aligned, and indefinite mutes show ∞. Hover for the exact end time. Server-wide and parent-room mutes are included, and expired indicators disappear automatically.

## Private conversations

Open another person's user card from a message author, mention, or member list, then click **Message**. SideTable opens an existing private top-level room with just the two of you, or creates a private room and adds that person. The new room has no title. Untitled private rooms appear with the other members' avatars and names, leaving out your own. Nothing is sent until you compose and send a message.

This requires an active, writable connection and a server that allows private rooms and adding other users. If adding the person fails, the card shows the server error; the newly created private room may remain in your room list. Group rooms and threads are not reused as one-to-one conversations.

## Messages and shortcuts

Return sends; Shift-Return inserts a line break. Command-K switches conversations, Command-F finds loaded messages, and Command-comma opens Settings. Right-click a message, including unselected text, for Reply, React, Start Thread, Edit, Copy Link, Copy Text, View Source, Move, and Delete. View Source shows the message record as formatted JSON, with a Copy button. When text is selected, right-click keeps the native text commands (including Copy for just the selection) and adds a **Message Actions** submenu. Plain text, Markdown paragraphs, headings, and code blocks share this behavior. The entire message is highlighted while its menu is open, without changing your text selection. Click the quoted line above a reply to jump to the original message; SideTable highlights it and loads older retained history when needed. Start Thread suggests a title and quotes the source in its description, then prepares a reply to that source in the new thread; it leaves the original message in place. Copy Link produces an Apron web link (recipients still need server access); it is unavailable for endpoints with query parameters to avoid sharing credentials. The emoji button and React open a compact picker with ten columns and ten visible rows. Filter by All, Recent, Favorites (the star), Server, or Unicode; Recent remembers your seven most recent Unicode selections across launches, filling unused slots with common choices. Search is focused when the picker opens. Press Down to start keyboard selection, use arrow keys to browse, Return to choose, and Escape to close. Hover over an icon to see its name, shortcode, category, or tags in the details footer and tooltip. Scroll to browse the full catalog. Right-click an emoji to pin/unpin it or copy its shortcode. All lists your recent emoji first, then favorites, then server emoji, then the rest, showing each emoji once; favorites also have their own star tab; Unicode favorites are shared across servers, while custom favorites belong to the current server and account. Hold Shift while selecting to insert multiple emoji or toggle multiple reactions without closing the picker. Emoji shortcode selections also update recents. Right-click a reaction badge to see the accounts that used it; select an account to open its profile. Left-click still toggles your reaction when posting is allowed. Type `@` for member completion, `#` for known rooms and threads, or `:name` for emoji. Arrow keys select a suggestion, Tab or Return inserts it, and Escape dismisses it. The `@` menu inserts a member reference at the caret. The smiley button opens a searchable emoji picker; reaction menus offer More emoji… for the same picker.

On servers that support commands, text starting with `/` is sent as a command, such as `/help`; start with `//` to post a message beginning with `/`. Replies appear in the conversation after the latest message at the time, marked with their sender (for example, “Only you”), and are visible only to you. Private notices that name no conversation, such as a server’s welcome, appear once below the conversations instead; dismiss one with its × button, and the same notice stays hidden if the server repeats it after reconnecting. They are not part of history and disappear when SideTable reconnects. A rejected command shows the server’s error below it.

Plain web URLs in messages are clickable, including messages sent without Markdown formatting. Code blocks and inline code stay literal.

While composing, up to three HTTP/HTTPS links appear as preview cards. Links inside code and Markdown images are excluded. Use a card’s × button to omit its preview while keeping the URL in the text; **Restore link previews** brings omitted cards back. These choices are saved with the draft for that conversation and account. Selected links are sent as embeds alongside any file attachments, so the server can enrich them and other clients can display them. Slash commands do not acquire automatic link embeds.

While you compose, macOS Link Presentation fetches website titles and preview images directly from the linked sites. Images appear above the card’s title when available; unavailable images leave a text-only card. GitHub links also acquire fallback titles and descriptions. Requests are debounced, cancelled when the draft changes, and cached in memory for the current conversation and account for up to an hour. SideTable also fetches the linked page directly and parses its OpenGraph tags locally, without a third-party metadata service. Sending never waits for these fetches: it includes available, unexpired text metadata and the original image URL in `og.image`, with dimensions, type, and alt text when provided; otherwise it sends just the link. The server may keep, replace, or drop this metadata and should proxy the image before broadcasting it. Received images remain subject to the server media-origin policy.

Edit your own message to rename uploaded files or remove attachments and link previews. Removing an uploaded file or stream asks for confirmation; changes apply only after Save Changes. Pending uploads cannot be removed or renamed. If the message changes elsewhere while the editor is open, reopen it before saving. Generated GitHub previews are labeled “Preview on this Mac”: hiding those is local to your account on this Mac and persists across launches; it does not alter the message for other clients. SideTable also remembers omitted previews for acknowledged outgoing messages locally, so its GitHub fallback does not immediately recreate them.

## Reading conversations and threads

Room and member listings are reused for 30 seconds during conversation navigation, and identical in-flight listing requests are shared. If the server rate-limits these requests, SideTable shows a retry countdown and pauses further listings for the server's requested delay. History loading continues; room, member, or thread details may be stale until you reopen the conversation or retry the action after the countdown. Reconnecting does not bypass the cooldown.

A **New** divider marks the first unread message in a conversation or thread. It stays at the unread boundary while you read earlier messages and clears when you scroll or jump back to the latest message in a visible panel of the active window. Opening a conversation that already shows its latest message keeps the divider in place. It is hidden while filtering messages.

Unread badges clear when the key window is displaying the latest messages, including when focus returns. Background, minimized, filtered, and older-history views do not mark conversations read or suppress alerts. Each conversation pane tracks its own attention; closing one cannot clear another pane's registration. Window navigation remains shared across windows.

Saved conversations keep up to 500 messages per conversation for the signed-in account, along with the position SideTable had reached in each conversation's history. On the next launch, within seven days, they appear immediately and SideTable downloads only the messages, edits, deletions, and reactions added since. Catch-up stops after five pages of 200 updates per conversation; past that limit the conversation starts again from its latest messages, and earlier messages load as you scroll back. The same limit applies when reconnecting. Both limits can be changed in Settings → Storage. While conversations are active, the saved copy is refreshed at most once a minute; anything newer is fetched on the next launch. Signing in with a different account discards the saved copy.

Settings → Storage shows saved-conversation sizes and offers per-server or global clearing. Clearing preserves live conversations, drafts, read markers, and sign-in, and prevents those saved copies from being recreated until the next launch. The saved-conversation size covers conversation files; downloaded media has a separate disk-usage display and clear control. Avatar memory is not included.

SideTable restores your panel workspace on the next launch. Existing installations without a saved panel layout migrate from the last selected server, room, and thread. Conversation positions use the saved message anchors described below.

Conversations reopen at the last viewed message, saved separately per server, account, and room or thread. SideTable loads older history when needed to restore that position. If the message is no longer retained, it uses the nearest available message; conversations without a saved position or read marker open at the latest message. Welcome notices and thread links appear above the messages. Browsing older history preserves your position and shows a count of new live messages. Choose that button to jump to the latest messages; sending also jumps to your outgoing message. At the bottom, new arrivals stay in view. Edits, reactions, and older-history pages do not add to the arrival count or force scrolling. Returning to the app preserves the current position; unread clears only in an active window displaying the latest messages.

Click a thread’s name to read its description as Markdown, preserving quoted source messages and multiline context. Opening a thread loads its replies directly, without depending on member or child-room listings. Reopening it or reconnecting refreshes its history; the thread header also offers Refresh. Viewing a thread does not join it, so unjoined threads need refresh to fetch later replies.

History initially loads up to 200 log changes per top-level room. “Load earlier messages” fetches another page; “Show earlier messages” reveals records already loaded. Loading errors offer retry. Search covers loaded messages, and unread counts reflect loaded history rather than the full server archive. Reconnect recovery fills changes since the last checkpoint before enabling writes.

Connections suspend during system sleep or network loss and recover when both the Mac and network are available. Server retry delays are respected; denied connections require an explicit reconnect. Interrupted sends remain available for explicit retry with their original operation IDs.

## Profile bios

On servers advertising `ext:bio` or `ext`, profile cards show a short plain-text bio, with clickable HTTP(S) links. Open your own profile and choose Add Bio… or Edit Bio… to update it. The limit is 250 Unicode code points; clearing the field removes your bio. Save errors leave your draft open. Bios are read from current profile data, not old messages.

## Avatars and attachments

Inline raster avatars, server-hosted avatars, and external HTTPS avatars load automatically. A shared in-memory cache reuses images across conversations, member lists, and profiles. Avatar updates refresh every view, including when the URL stays the same. The cache clears on sign-out or account changes. Invalid or unavailable images show initials.

The members panel lists active members first, then sorts names alphabetically. A green dot marks active members, and role badges show server-provided roles such as admin. Search by name, user ID, or role. Hover over a member for status, roles, and bio; click to open the full profile. Presence indicators are hidden while disconnected or viewing saved data. Drag the divider on its left edge to resize it between 220 and 400 points, or double-click the divider for the default width. Whether the panel is expanded, and its width, are restored on launch.

Paste a screenshot or copied file into the message composer to attach it to the current draft, with or without existing text. To capture a screenshot to the clipboard, press Control–Shift–Command–4 and select an area, then click the composer and press Command–V. Ordinary copied text stays text; pasted attachments are sent only when you send the message. You can also drag files or images anywhere onto a conversation; it is outlined while a drop will be accepted. Files attach as they are, images dragged from a browser, Photos, or Preview keep their original format, and dragged text and links are not attached. Drops are not accepted when the server does not support uploads.

Attachment images appear inline within 420 × 300 points; click to open Quick Look. File cards offer Preview and Save, with additional actions in their context menu. Link cards show the server-provided Open Graph title, site name, description, and thumbnail. Preview metadata supplied by Apron takes precedence. For public GitHub PRs, issues, commits, and repositories without a preview, SideTable fetches a fallback from GitHub’s unauthenticated API (up to three links per message, excluding code). API results are cached for an hour; unavailable or private links fall back to their URL details. Received messages do not trigger website preview fetches through Link Presentation. Their media loads from the chat server and its declared media origins.

Downloaded attachments and sent-message preview images are cached on disk across launches, separately for each server and account. Reopening or saving a cached attachment reuses its bytes. Inline images also keep a small downsampled copy, so later launches show them without decoding the original; rows reserve the image’s size while it loads. The cache keeps up to 256 MiB and evicts the least recently used files. Temporary Quick Look copies count toward this limit and disk usage, remain available while open, and are removed when dismissed. Settings > Storage > Clear Downloaded Media removes these copies and closes previews; signing out clears that server’s media. Automatic image downloads are capped at 8 MiB; explicit downloads at 64 MiB. Files already cached can display without another network request. The system may purge the cache when disk space is needed.

The Dock icon shows the total unread message count across all servers and conversations. macOS asks for badge permission when unread messages first appear; allow it to show the count. If badges are disabled, enable them in System Settings > Notifications > SideTable. This is separate from SideTable’s mention-and-reply alerts. The badge clears when no unread messages remain and keeps updating while SideTable is running with its windows closed.

Closing the last window keeps sessions running. **Quit** ends connectivity and notifications. Apron servers can read the messages they host; transport uses TLS, not end-to-end encryption.

## Sharing and opening links

Same-server Apron links in messages show preview cards for rooms, threads, messages, and profiles. Cards use the current account’s loaded data; missing messages show a basic open-to-view label. Previews do not fetch history or join rooms, and local preview details are not submitted as message metadata. Click a card to navigate directly.

Shared message links use Apron’s standard `https://link.apron.chat/#server=…&room=…&message=…` format; threads use their own room ID. Choose **File > Open Link…** (⌘L) to paste an HTTPS or `apron:?` link. Links within the same Apron server navigate directly; links to other servers and invite/sign-in links require destination review. SideTable can open rooms, threads, messages (loading older retained history as needed), and user profiles. Invite/sign-in links require an explicit **Sign In** action and cannot replace an already signed-in account. Links never automatically join rooms. SideTable registers `apron:` and `sidetable:` URL handlers. For example, `sidetable://open?server=wss://server.apron.chat/&room=general` opens the destination-review dialog. Install and launch the updated app before using links from a browser. See [browser link integration](deep-links.md) for the `link.apron.chat` setup.

Click the server icon (or right-click the server name and choose **Server Details…**) to see its live description and address. The details sheet can copy the address or share a server link; sharing is unavailable for endpoints containing query strings, which may hold credentials.

When a server asks SideTable to wait, the composer or loading controls show a countdown. Affected Send, Retry, and history/room-loading buttons become available when the delay ends. Commands without attachments remain available during an upload-only cooldown. SideTable never automatically resends a blocked write.

The attach button opens the file chooser directly; hover over it to see the server’s accepted file types, size limits, and image resizing limits. Selected, pasted, and dropped files are checked before being attached, and a file the server would reject shows an error instead; sending checks the current limits again. Avatar and emoji commands use their own advertised limits.

When a server advertises a private-room limit, Server Details, Browse Rooms, and the private-room creation form show your usage. Joined private rooms count toward the limit; threads do not.

Open **Servers → Manage Server** (or **Manage Server** in the sidebar’s server menu) to change the title, description, or icon, and to add, replace, or remove custom emoji. Management opens in a separate window attached to that server, so you can keep chatting or switch servers while it is open. Opening management for the same server brings its existing window forward. Each field saves separately. Choose a server icon, then press its upload button; removing the icon asks for confirmation. **Manage Server Emoji** slides out a grid of the server’s emoji, including hidden entries. Choose an image and name, then **Add to Changes**, or select an existing emoji and **Remove**. Additions, replacements, and removals stay local until **Save**. Use **Undo Change** or **Discard** to cancel pending edits. Save sends changes in sequence and stops at the first failure; completed changes are not sent again. Pending edits survive hiding the panel or closing management, but are cleared on sign-out or quitting. These controls use the protocol’s suggested commands; the server decides which commands and permissions are available. Failed operations show the server’s response, and uploads remain visible when you reopen Manage Server.

Reference a room or thread with `#room_id`, for example `#1791590929296`. Known references display the room/thread title and open that conversation on the message’s server. Unknown IDs stay as written. Code spans, code blocks, and existing links stay literal. Type `#` in the composer to search known rooms and threads; the inserted text retains the actual ID.

Compose and Edit Message show known `@user_id` and `#room_id` references as compact name tokens. Hover to see the raw ID; copying and sending retain that ID. Backspace removes a whole token, and Undo/Redo restores the raw text. Unknown references stay as typed. In the editors, Markdown styling is limited to inline backtick code and code blocks, including language-labelled fences. Delimiters and language names remain visible; bold, italics, and headings stay unstyled; references inside code or explicit links stay literal. Return inserts a newline in Edit Message; the composer keeps Return to send and Shift-Return for a newline.

**Edit…** opens the selected message in the conversation’s compose area. Its row is highlighted while editing. Your unsent draft and staged attachments are kept separately and return after **Save Changes** or **Cancel**. Press Escape to cancel or Command-Return to save; Return inserts a newline. Existing attachment rename/removal controls remain available in the editor.

## Troubleshooting diagnostics

Choose **Help → Copy Diagnostics** shortly after a blank transcript or a room-refresh cooldown appears. Paste the report with the steps that triggered the problem. Logging is automatic in this build and does not require restarting or reconnecting to begin capture.

The local journal records history and room-list request attempts, completion times, numeric errors and retry delays, cache hits, coalesced loads, and cooldown skips. Triggers distinguish room opens, manual refreshes, link navigation, older-history loads, initial connection recovery, and reconnect recovery. Transcript samples record the scroll offset, viewport/document heights, and number of visible message-row anchors after layout settles; unchanged samples are suppressed. A zero row count can also mean an empty room or a viewport showing only notices, so include what you expected to see.

Message text, request/response bodies, error descriptions, credentials, server addresses, and raw room IDs are excluded. Server and room identifiers are salted anonymous hashes that change on each app launch. Nothing is uploaded automatically; Copy Diagnostics places the report on the clipboard.

The journal keeps two files of at most 256 KiB each under `Sidetable/Diagnostics` in the app's Application Support directory (inside its macOS sandbox container). Older entries rotate out automatically. If disk writes fail, copying diagnostics falls back to the most recent 256 KiB in memory and reports that limitation.
